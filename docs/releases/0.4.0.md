# Linux Supply Chain Guard 0.4.0 — local web exposure review

This release adds read-only checks for management-panel configuration,
cache/session-store risks and unexpected changes in explicitly selected
webroots. Supported configuration checks run in the default scan. Webroot
hashing requires `--webroot`; comparison requires a separately trusted
`--web-baseline`.

## New checks

- Webmin/Usermin listener and explicit TLS-off settings, local Cockpit socket
  declarations, and supported Compose management-panel images with published
  ports or host networking.
- Redis bind and explicit protection/authentication settings; Memcached bind,
  UDP and Unix-socket settings; PHP network session handlers and local
  file-session directory permissions. Session records are not read by these
  configuration checks.
- SHA-256, size and Unix-mode manifests for selected webroots. A valid baseline
  identifies added, removed, content-changed and permission-changed files,
  including hidden files and dependencies. Baselines are never trusted or
  refreshed automatically.
- Bounded Linux descriptor-anchored inspection. Discovered symlinks are not
  followed; unreadable, unsupported, changing, excluded, special or oversized
  input produces incomplete coverage instead of a clean result.

See the [supported formats, limits and baseline workflow](https://github.com/Dragon-Lady/linux-supply-chain-guard/blob/v0.4.0/docs/web-exposure.md).

## Interpretation and compatibility

Runtime exposure remains **unknown**. Local declarations cannot establish
internet reachability, effective authentication, compromise or PHP patch
status. Webroot differences need operator review; normal deployments also
change files. Matching a baseline does not prove that a site is uncompromised.
The checks make no network requests, execute no target code, and change no
service settings or target files. Keep reports private.

JSON gains `webExposure`; new findings may change previous zero exits to
review (1) or incomplete (3). Existing exit precedence remains
4 > 2 > 3 > 1 > 0. Unsupported Compose features and runtime overrides still
need separate review. See the scope document before interpreting an empty
result as evidence about a service.

The motivating [Cairn investigation](https://norforge.com/blog/inside_cairn)
is separate from the [PHP advance notice](https://www.php.net/archive/2026.php).
These checks do not attribute activity to that campaign or provide universal
webshell detection. PHP readiness continues to report unknown patch status;
affected and fixed versions were still undisclosed in the official October 20
notice when this release was prepared.

## Verification and download

The full test suite includes 36 web-check cases and four new CLI integration
cases covering risky and restricted configurations, baseline differences,
redaction, resource limits, links, read failures and read-only behavior.
Release verification also exercises the installed tarball, exact outgoing
source range and complete package with Push Guard.

This is a GitHub release with an npm-format tarball and SHA-256 manifest.
Download both assets to the same directory, then run:

```sh
sha256sum --check SHA256SUMS
npm install --global ./linux-supply-chain-guard-0.4.0.tgz --ignore-scripts
```

npm registry publication remains a separate gated operation.
