# Linux Supply Chain Guard 0.5.0

This release adds opt-in, read-only triage for the October 2026 UpdraftCentral
Cloud key compromise. Operators can inspect selected WordPress plugin trees,
plain-text logs, and a sanitized JSON projection of key counts and account
capabilities. The scanner does not execute PHP, bootstrap WordPress, contact
a database, revoke credentials, or modify the inspected site.

- `--wordpress-root DIR`: inspect conventional plugin, must-use plugin and
  unpacked upgrade trees for published markers and suspicious code patterns.
- `--updraft-log FILE`: identify published probe, command, client and trigger
  markers without printing raw requests or query tokens.
- `--wordpress-evidence FILE`: review remaining cloud/unclassified connection
  counts and administrative capabilities on non-administrator accounts.

Missing, linked, unreadable, malformed or limited inputs produce incomplete
coverage. Unselected layers are labelled explicitly. Every result retains
unknown compromise status: neither no matches nor an installed version proves
that a site is clean. Account checks require a trusted sanitized export;
there is no live database exporter. See [usage and boundaries](../updraft-review.md).

The vendor names UpdraftPlus 1.26.13 / 2.26.13 as its revocation release;
Nethemba reports a remaining-key cutoff gap. Verify connections directly and
investigate existing backdoors. Follow the current primary advisories:

- https://teamupdraft.com/blog/security-incident-october-2026/
- https://patchstack.com/articles/updraftcentral-key-compromise-wordpress-backdoors/
- https://nethemba.com/updraftcentral-backdoor-analysis/

The v0.4.1 procfs-coverage and simultaneous content/permission corrections are
preserved. PHP core patch readiness remains a separate, unknown-status check.

Validation includes the full regression suite, 15 focused incident-check tests,
packaged CLI smoke coverage, and Push Guard checks of source and package.
